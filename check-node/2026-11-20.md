# 2026-11-20 打卡（Task 2：P1 + D1 + I1）

## 学习 / 实践内容

### 一、P1：AI Agent 场景识别

P1 给我最大的提醒是：比“怎么做 Agent”更重要的是“值不值得做”。

课里先唱反调，列了三类其实不需要 Agent 的场景：固定答案的 FAQ、结构化数据查询、对准确性零容忍的计算。我对照自己以前的想法，确实很容易一上来就想“上个 Agent”，但很多需求用静态页面、BI 看板或一段确定性代码就能解决，硬上 Agent 反而更慢、更贵、更容易出错。

真正要做判断时，课里给了三维度：数据可得性、任务可定义性、流程编排选择。其中数据可得性是最重要也最容易在立项阶段验证的——列 10 个典型问题，去找答案数据在哪，如果一半以上找不到，先别做 Agent，先补数据。任务可定义性则要看有没有“事实锚点”，以及输出表述的弹性边界；流程编排要在 Agent 和 Workflow 之间做选择，第一次做 AI 项目优先 Workflow，再逐步增加自主性。

Agent 的甜区是三类：用户意图模糊需要语义理解、需要调用外部工具/API、任务复杂需要持续交互。P1 最后那句“90% 的 AI 功能失败不是模型不行，而是立项时没人问数据在哪”，和我之前的经历很对上：我用 Opus 5.5 做实验，模型已经很强，但数据质量不高、标签也不是金标，最后效果就是上不去。问题不在模型层，而在数据层。

### 二、D1：大模型 API 基础

D1 把“用 ChatGPT”和“用 API 构建 AI 应用”之间的差别讲清楚了。

对话的本质是一个消息列表：system 定人设，user 是用户输入，assistant 是模型回复。模型本身没有记忆，多轮对话就是每次把历史消息重新发一遍。这正好接上 F1 的上下文窗口——所谓“记忆”，在工程上就是你自己维护的消息列表。

流式输出让我印象很深：首 Token 延迟比总生成时间更重要。用户能接受“边生成边看”，不能接受“等十几秒再一次性出现”。生产环境里面向用户的回答默认应该用 Streaming。

Tool Use 是这一节的重点，也是 Agent 的分界线。关键洞察是：模型不能上网、不能查库、不能执行代码，它唯一能做的是“说”。Tool Use 的流程是模型声明要调用什么工具和参数，我的代码去执行，再把结果作为 ToolMessage 传回去，模型基于结果继续推理。模型是指挥，代码是执行者。LangChain 里用 `@tool` 定义工具、`bind_tools` 绑定、`tool_calls` 接收调用、`ToolMessage` 回传结果；d1_1 到 d1_6 的演进把“手写循环”到 `create_agent` 一行创建 Agent 的过程展示得很清楚。

我之前的误区是以为工具调用是模型的内置能力，现在明白它其实是模型和代码之间的协作协议。也更能理解 D1 结尾那句：Tool Use 是管道，数据才是水。

### 三、I1：AI 原生数据库基础

I1 纠正了我一个很大的偏见：以前我觉得“有向量类型”就是 AI 原生数据库，其实向量只是其中一个维度。

AI 原生数据库要看六个维度：多类数据、混合检索、事务与恢复、模型调用、Agent 工作流、交付形态。Agent 的 RAG、记忆、任务执行、业务决策、试验修正，背后都需要数据层保证召回、更新、追踪、一致性和隔离。传统“关系库 + 向量库 + 搜索引擎”三套系统不是不能用，但会带来同步延迟、权限规则重复实现、多路结果在应用层拼接等隐性成本。

I1 还讲了统一架构的六层、SQL 为什么仍然重要、MVCC/Redo Log、LSM-Tree、一份事实多种表达、混合检索与 RRF、同步/异步索引、数据库内 AI（`AI_EMBED`、`AI_RERANK`、`AI_COMPLETE`），以及 Fork/Diff/Merge 给 Agent 的可写沙箱。最实用的一条是模型调用顺序：先过滤 → 再召回 → 缩小候选集 → 最后重排或生成，不要对无限结果集逐行调用模型。

这一节和 F2 的“统一数据引擎 vs 三个独立系统”接上了，也让我更期待后面的 D2 和 I2：先把数据底座搭起来，再谈检索效果。

## 四、遇到的问题与解决

- P1 的 Checklist 看起来简单，但“任务可定义性”实际最难填：同一个事实可以用很多种表述，哪些算对、哪些算错，需要先约定事实锚点和评估口径。
- D1 的 d1_6 用的是阿里云百炼的 `qwen-plus`，和 d1_1～d1_5 的硅基流动 Key 不是同一套；跑示例前要确认对应平台的 Key 和模型是否开通。
- I1 的概念密度比较高，RRF、同步/异步索引、Fork/Diff/Merge 这些细节先建立框架，具体实现留给 I2、I3、I5 再深入。
